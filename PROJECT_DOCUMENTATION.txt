SLIDE 2 - INTRODUCTION & RATIONALE (Why this problem?)
--------------------------------------------------------------

WHAT IS THIS PROJECT?
  Digital Parcel Repository is a web-based hostel parcel
  management system. When a parcel arrives at the hostel gate,
  the admin logs it in the system. The system automatically
  generates a 4-digit OTP and emails it to the student.
  The student shows the OTP to collect their parcel.
  The admin verifies it and marks the parcel as collected.

WHY DID WE BUILD THIS?
  - Hostels receive dozens of parcels every day from couriers
    like Amazon, Flipkart, DTDC, BlueDart etc.
  - Currently, most hostels use a manual paper register to
    record parcels. This is slow, error-prone, and inefficient.
  - Students are not notified when their parcel arrives.
    They have to physically visit the gate every day to check.
  - Parcels sit uncollected for days because students don't know
    they have arrived. This creates storage problems.
  - There is no proof of delivery. Anyone can claim a parcel
    without verification.
  - We built this system to solve all these problems using
    simple web technology that any hostel can use.

KEY MOTIVATION:
  - Real problem faced by real students every day
  - Simple solution using modern web technology
  - Fully automated notification via email
  - Secure OTP-based parcel release system

SLIDE 3 - PROBLEM STATEMENT
--------------------------------------------------------------

CURRENT PROBLEMS IN HOSTEL PARCEL MANAGEMENT:

  1. MANUAL REGISTER SYSTEM
     - Parcels are recorded in a physical paper register
     - No digital record, no search, no history
     - Easy to lose or damage records

  2. NO STUDENT NOTIFICATION
     - Students are never informed when their parcel arrives
     - They must visit the gate daily to check manually
     - Parcels remain uncollected for days or weeks

  3. NO PROOF OF DELIVERY
     - Anyone can walk up and claim a parcel
     - No verification of identity
     - Risk of wrong person collecting the parcel

  4. ADMIN OVERLOAD
     - Admin has to manually search through registers
     - No way to quickly find all parcels of one student
     - No visibility into how many parcels are pending

  5. NO OVERDUE TRACKING
     - No system to flag parcels that have been sitting
       uncollected for too long (72+ hours)
     - Storage space gets blocked by uncollected parcels

  6. NO DIGITAL HISTORY
     - Once a parcel is collected, there is no record
     - Cannot check past parcel history for any student

PROBLEM STATEMENT (Formal):
  "The existing manual parcel management system in hostels
  lacks automation, student notification, identity verification,
  and digital record keeping. This results in uncollected
  parcels, storage issues, and security risks. A digital
  solution is required to automate parcel logging, notify
  students via email, verify identity using OTP, and provide
  the admin with a real-time dashboard."

SLIDE 4 - REFERENCES (Existing Models)
--------------------------------------------------------------

EXISTING SYSTEMS WE STUDIED:

  1. FEDEX / BLUEDART TRACKING SYSTEM
     What it does : Courier companies provide online tracking
                    of parcels using tracking IDs.
     Limitation   : Only tracks the parcel in transit.
                    Does not manage last-mile hostel delivery.
     Our solution : We handle the last step - from hostel gate
                    to student room - which these systems ignore.

  2. COLLEGE COURIER MANAGEMENT APPS (Research Papers)
     Reference    : "Smart Parcel Management System for
                    Educational Institutions" - IEEE 2022
     What it does : Proposes digital parcel logging for
                    college campuses using QR codes.
     Limitation   : Requires QR code scanner hardware.
                    Complex setup for small hostels.
     Our solution : We use simple email OTP. No hardware
                    needed. Works on any device with a browser.

  3. INDIA POST / SPEED POST TRACKING
     What it does : Government postal tracking system for
                    registered letters and parcels.
     Limitation   : Only tracks up to delivery point.
                    No hostel-level management.
     Our solution : Picks up exactly where these systems stop -
                    managing parcels after they reach the hostel.

SLIDE 5 - OBJECTIVES
--------------------------------------------------------------

THE 8 OBJECTIVES OF THIS PROJECT:

  1. DEVELOP a secure user authentication system using
     JWT tokens and bcrypt password hashing for both
     admin and student roles.

  2. IMPLEMENT role-based access control so that admin
     and student see different pages and have different
     permissions within the same application.

  3. DESIGN an admin dashboard that shows real-time stats -
     total parcels today, pending pickups, and overdue
     parcels (72+ hours uncollected).

  4. AUTOMATE email notification using Nodemailer and
     Gmail SMTP so students receive a 4-digit OTP
     immediately when their parcel is logged.

  5. IMPLEMENT a secure OTP-based parcel release system
     where the OTP is single-use only and expires after
     the parcel is collected.

  6. ENABLE admin to search all parcels of any student
     by entering their roll number.

  7. PROVIDE students with a personal parcel history page
     showing all their parcels with current status
     (Arrived or PickedUp).

  8. BUILD the entire system using the MERN stack
     (MongoDB, Express, React, Node.js) following a
     clean REST API architecture.

SLIDE 6A - SYSTEM ARCHITECTURE (Overall)
--------------------------------------------------------------

3-TIER ARCHITECTURE:

  TIER 1 - FRONTEND (React.js)
  --------------------------------
  - Built with React.js + Vite + Tailwind CSS
  - Runs in the browser at http://localhost:5173
  - Pages: Login, Register, Dashboard, My Parcels
  - Communicates with backend using HTTP requests via Axios
  - Stores JWT token in browser localStorage

  TIER 2 - BACKEND (Node.js + Express.js)
  ----------------------------------------
  - Built with Node.js runtime + Express.js framework
  - Runs at http://localhost:5000
  - Exposes REST API endpoints under /api/
  - Handles authentication, parcel logic, OTP, email
  - Validates JWT token on every protected request

  TIER 3 - DATABASE (MongoDB Atlas)
  ------------------------------------
  - Cloud-hosted MongoDB database (MongoDB Atlas)
  - Two collections: users and parcels
  - Connected via Mongoose ODM
  - Stores all user accounts and parcel records

DATA FLOW:
  User clicks button in React
    → Axios sends HTTP request to Express API
      → Express validates JWT token
        → Express queries MongoDB via Mongoose
          → MongoDB returns data
            → Express sends JSON response
              → React updates the UI

SLIDE 6B - MODULE BLOCK DIAGRAM
--------------------------------------------------------------

THE 4 MAIN MODULES:

  MODULE 1: AUTHENTICATION MODULE
  ---------------------------------
  File     : server/routes/auth.js
             server/middleware/auth.js
             server/models/User.js
  Input    : name, rollNumber, email, password, role
  Process  : Hash password with bcrypt
             Create user in MongoDB
             Sign JWT token (valid 7 days)
             Verify JWT on every protected request
  Output   : JWT token + role + name sent to frontend

  MODULE 2: PARCEL MANAGEMENT MODULE
  ------------------------------------
  File     : server/routes/parcels.js
             server/models/Parcel.js
  Input    : trackingId, courierCompany, recipientRoll
  Process  : Find student by roll number
             Generate 4-digit random OTP
             Save parcel to MongoDB
             Trigger email notification
  Output   : Parcel saved, OTP emailed to student

  MODULE 3: OTP RELEASE MODULE
  ------------------------------
  File     : server/routes/parcels.js (PATCH /release)
  Input    : 4-digit OTP entered by admin
  Process  : Search for parcel with matching OTP
             Check parcel status is still "Arrived"
             Update status to "PickedUp"
             Clear OTP from database (single use)
  Output   : Parcel marked as PickedUp, OTP invalidated

  MODULE 4: DASHBOARD & NOTIFICATION MODULE
  -------------------------------------------
  File     : server/routes/parcels.js (GET /dashboard)
             server/utils/mailer.js
             client/src/pages/Dashboard.jsx
  Input    : Admin requests dashboard data
  Process  : Count today's parcels
             Count all pending parcels
             Count overdue parcels (72h+)
             Fetch all pending parcel details
             Send HTML email via Gmail SMTP
  Output   : Stats shown on dashboard
             Email delivered to student inbox

SLIDE 6C - ALGORITHM / WORKFLOW
--------------------------------------------------------------

COMPLETE PARCEL LIFECYCLE (Step by Step):

  STEP 1: PARCEL ARRIVES AT HOSTEL GATE
    - Courier delivers parcel to hostel gate
    - Admin receives the physical parcel

  STEP 2: ADMIN LOGS THE PARCEL
    - Admin opens the Dashboard page
    - Fills in: Tracking ID, Courier Company, Student Roll Number
    - Clicks "Log Parcel" button

  STEP 3: SYSTEM PROCESSES THE REQUEST
    - Frontend sends POST /api/parcels to backend
    - Backend middleware checks JWT token (admin only)
    - Backend finds student in database using roll number
    - Backend generates a random 4-digit OTP (e.g. 7342)
    - Backend saves parcel to MongoDB with status = "Arrived"

  STEP 4: EMAIL SENT TO STUDENT
    - Backend calls Nodemailer with student's email
    - Gmail SMTP sends HTML email to student
    - Email contains: tracking ID + 4-digit OTP
    - Student receives email on their phone/laptop

  STEP 5: STUDENT COMES TO COLLECT
    - Student visits hostel gate with their OTP
    - Student shows OTP to admin (e.g. 7342)

  STEP 6: ADMIN VERIFIES OTP
    - Admin enters OTP in the Release Parcel form
    - Clicks "Verify & Release" button
    - Backend searches for parcel with that OTP and status = "Arrived"
    - If found: status updated to "PickedUp", OTP cleared to ""
    - If not found: error "Invalid or already used OTP"

  STEP 7: PARCEL RELEASED
    - Admin hands over the parcel to the student
    - Dashboard stats update automatically
    - Student can see "PickedUp" status on My Parcels page

OTP SECURITY RULES:
    - OTP is 4 digits (1000 to 9999)
    - OTP has NO time expiry
    - OTP is SINGLE USE ONLY
    - Once used, OTP is cleared from database
    - Cannot be reused even if someone knows it

SLIDE 6D - DATABASE SCHEMA
--------------------------------------------------------------

COLLECTION 1: users
---------------------
Field        Type      Required   Unique   Description
-----------  --------  ---------  -------  ---------------------------
_id          ObjectId  auto       yes      MongoDB auto-generated ID
name         String    yes        no       Full name of the user
rollNumber   String    yes        yes      Unique roll number (student ID)
email        String    yes        yes      Email address for login & OTP
password     String    yes        no       bcrypt hashed password (never plain text)
role         String    yes        no       Either "student" or "admin"
                                           Default value is "student"

COLLECTION 2: parcels
-----------------------
Field           Type      Required   Description
--------------  --------  ---------  ----------------------------------
_id             ObjectId  auto       MongoDB auto-generated ID
trackingId      String    yes        Courier tracking number (e.g. AMZ123)
courierCompany  String    yes        One of: Amazon, Flipkart, DTDC,
                                     BlueDart, Other
recipient       ObjectId  yes        Reference to _id in users collection
                                     (links parcel to a student)
otp             String    no         4-digit OTP. Cleared after collection.
                                     Default is empty string ""
status          String    yes        Either "Arrived" or "PickedUp"
                                     Default is "Arrived"
createdAt       Date      auto       Auto set by MongoDB timestamps
updatedAt       Date      auto       Auto updated by MongoDB timestamps

RELATIONSHIP:
  parcels.recipient  →  references  →  users._id
  One student can have many parcels (One-to-Many)

HOW TO RUN THIS PROJECT
--------------------------------------------------------------

STEP 1: Start MongoDB
  Make sure MongoDB is running OR use MongoDB Atlas (cloud)
  Your project uses Atlas - connection is in server/.env

STEP 2: Setup Backend
  Open terminal, go to server folder:
    cd server
    npm install
  Edit .env file with your values (already done)
  Create admin user:
    node seed.js
  Start backend server:
    npm start

STEP 3: Setup Frontend
  Open a new terminal, go to client folder:
    cd client
    npm install
    npm run dev

STEP 4: Open in Browser
  Go to: http://localhost:5173
  Admin login: admin@hostel.com / admin123
  Or register a new student account

API ROUTES SUMMARY:
  POST   /api/auth/register          Register a student
  POST   /api/auth/login             Login (admin or student)
  POST   /api/parcels                Admin: log new parcel
  GET    /api/parcels/mine           Student: view own parcels
  PATCH  /api/parcels/release        Admin: verify OTP, release parcel
  GET    /api/parcels/search?roll=X  Admin: search by roll number
  GET    /api/parcels/dashboard      Admin: get dashboard stats
